# Agent guide

- This is a fully static Aion 2 wiki: React, TypeScript, React Router, and Chakra UI. Publish only `build/client`; keep runtime SSR disabled.
- Use Node from `.nvmrc` and npm 12.1.0 on Linux or macOS (WSL counts as Linux). Never reuse a `node_modules` installed from another operating system; delete it and run `npm ci`.
- Use Chakra components and shared tokens in `app/components/ui/theme.ts`. Preserve responsive layouts, keyboard access, reduced motion, and readable no-JavaScript content.
- For UI/design reviews or changes, read [DESIGN.md](DESIGN.md) before planning or editing and keep it current when design decisions change. Code is the design source of truth; there is no Figma file.
- Preserve all imported guide text, numbers, figure placements, source links, highlights, and the source's own regional/uncertainty wording. Articles render source content and original images only: do not add editorial audit notes, screenshot transcriptions, or status boilerplate. The one exception is the marker key for numbered/colored markers actually drawn on a screenshot (figure `annotations`). Remove Google Docs leftovers only through coverage `omitted`/`strayText` entries (see README), never by deleting content silently. Do not invent game facts or weaken integrity checks.
- Edit canonical content in `app/content/chapters/` and `app/content/source-overview.json`; run `npm run content:generate` after content changes. Do not hand-edit generated catalogues.
- Pull Google Doc updates with `npm run source:sync` on a branch (see README); the `source-sync` workflow does this once a day and opens or updates a pull request on `content/doc-sync`, and a Claude step tries to place flagged items there when `ANTHROPIC_API_KEY` is set. When running as that step, leave an item pending rather than guess where it belongs. The source baseline changes only through that command; never hand-edit it or loosen a check to absorb a Doc change.
- Search metadata is derived from content at build time: route `meta` exports go through `pageMeta()` or `notFoundMeta()` in `app/seo.ts`, which owns the production origin, canonical links, preview tags, structured data and the sitemap/robots output. Don't hand-edit it or hard-code the origin elsewhere. When a published URL changes or disappears (renamed slug, or a split, merged or deleted article), add a 301 in `netlify.toml` from the old path to its replacement. A new kind of page must be added to `isIndexable`; for a domain change, follow `docs/deployment.md`.
- Run `npm run check` for changes, and `npm run build` before delivery of application/build changes. For UI changes, also run `npm run verify:browser` after building (install Chromium with `npx playwright install --with-deps chromium`). Documentation-only edits need formatting/link checks.
- Keep tests minimal: test generic behavior with small fixtures, not article wording, game values, fixed catalogue counts, or framework internals. Source fidelity belongs in the existing integrity/static validators. Run focused tests while iterating, then required checks once before delivery; do not repeat passing suites without a relevant change. Browser QA is a representative smoke check, not an exhaustive article audit.
- Keep changes focused and preserve unrelated work. Do not commit secrets, `.local-tools`, dependencies, or build output.
- Follow `README.md` for development and `docs/deployment.md` for releases. A push to Netlify's connected production branch can deploy the site; push or publish only when requested.
