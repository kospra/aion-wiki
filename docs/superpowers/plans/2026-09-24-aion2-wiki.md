# Aion 2 Wiki Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Initialize a beautiful, accessible React wiki with local sample content, working search, and fully static production output.

**Architecture:** React Router framework mode supplies Vite integration, route modules, and build-time prerendering. Typed local content drives category navigation, article pages, search, and generated URLs. Components own local interaction state; no backend is required.

**Tech Stack:** React, TypeScript, React Router, Vite, CSS, npm, ESLint, Prettier, Vitest, React Testing Library.

**Spec:** `docs/superpowers/specs/2026-09-24-aion2-wiki-design.md`

## Global Constraints

- Use React Router framework mode with Vite and strict TypeScript.
- Disable runtime server rendering and prerender the homepage, category pages, and all local article routes at build time. The production output must run on static hosting without an application server.
- Use npm and commit a lockfile. Resolve supported stable dependency versions during implementation.
- Include a small set of explicitly labeled sample entries to demonstrate the structure. Do not present invented game mechanics or statistics as verified Aion 2 information.
- Support narrow mobile screens and desktop layouts.
- Do not add authentication, a database, a CMS, global state libraries, analytics, or deployment-provider configuration in this initialization.
- Use CSS decoration and a cohesive icon treatment; the scaffold does not depend on copyrighted game artwork or remote images.

## Review Focus

1. Search text containing capitals or surrounding spaces should return the same results as normalized input; test in Task 2.
2. Search and category filters yielding no results should preserve controls and offer an effective reset; test in Task 2.
3. A direct article URL should serve actual article HTML before JavaScript executes; verify every route in Task 3.
4. Invalid article/category slugs should show a useful not-found page rather than crash; test in Task 2 and inspect host behavior in Task 3.
5. Keyboard users and users at 200% zoom or with reduced motion should retain usable navigation and readable content; inspect in Task 3.
